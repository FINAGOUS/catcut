# CatCut v2 — S3 调色与画面（设计文档）

> 阶段：S3。依据：`v2-架构方案.md` §4/§5/§12、`v2-三家深度调研.md` §3/§6、
> `research_notes/catcut-v2/dogsc.md` §2.3–2.6/§6.1。
> DogSC 原版没有调色（全仓检索零命中），调色是 CatCut 层的新设计；
> 运镜/画布语义按 DogSC 的行为规格抄，不抄代码。

## 0. 结论先行

- 调色链固定顺序：**输入转换 → 白平衡 → HSL 分区 → 色轮 → 曲线 → LUT → 输出转换**，
  实现在 `core/ColorGrade`（CPU 参考）与 `shaders/grade.frag`（GPU 直播预览）两处，
  数学逐行对照，同一组常量、同一顺序。
- GPU shader 选了 **QRhi shader，不用 FFmpeg lut3d**（理由见 §1）。
- 预览与导出同一渲染路径：`TimelineEvaluator → FrameScene → TimelineFrameRenderer`，
  导出入口是 `media/ExportFrameRenderer::renderExportFrame`（S4 的种子），
  verify-s3 证明两者像素均值误差 < 1%。
- 运镜、画布、柔化/突出、光标轨道按 DogSC 语义做（§4–§6），全部归一化坐标。
- 美颜与人像抠像背景互斥（W5 已验证的限制，沿用）；无遮罩时美颜整帧轻处理，
  不再是硬错（W5 的“缺遮罩即硬错”不沿用）。

## 1. 调色：为什么选 QRhi shader，不选 FFmpeg lut3d

| 维度 | QRhi shader（选了） | FFmpeg lut3d（没选） |
|---|---|---|
| 参数变化成本 | uniform 更新，滑杆每动一格只传几个 float | 每动一格要在 CPU 上重烤一个 17³ LUT 再上传 |
| 表达能力 | HSL 七区权重、色轮分区权重、曲线表、白平衡增益都是原生计算 | 只能表达“逐像素查表”，分区权重必须先烤进表里，烤表本身就有量化 |
| 精度 | 全程 float32，只在曲线/LUT 纹理处 8-bit 量化（≈0.4%） | 17³ 网格插值 + 8-bit，暗部断层更明显 |
| 与其它级的关系 | 与示波器/美颜/遮罩共用同一套参数对象 | lut3d 是 filter graph 里的一级，与合成器两套参数 |
| 风险 | 需要一台真机验证 GPU 与 CPU 的像素一致性（CI 无 GPU） | 无 |

代价说清楚：CI 只能证明 shader 编译通过（qsb）+ 资源能加载（verify-s3 第 7 组），
**不能证明 GPU 画面与 CPU 画面逐像素一致**。GPU 与 CPU 的一致性是真机验证项
（用户电脑 RTX 4060 Ti 上跑同一帧对照），不在云端绿的范围内。
CPU 参考路径（`ColorGrade::applyPixel`）是权威实现：预览的 CPU 回退路径与导出
都走它，verify-s3 用解析值把它钉死。

工作空间：输入 `pow(c, 2.2)`（sRGB→线性近似），输出 `pow(c, 1/2.2)`；
恒等调色精确往返（float 误差内）。白平衡是线性增益：
色温 `r *= 1+0.4T, b *= 1-0.4T`，色调 `g *= 1+0.3t, r/b *= 1-0.15t`。
HSL 七区中心（turns）：红 0、橙 1/12、黄 2/12、绿 4/12、青 6/12、蓝 8/12、品红 10/12，
三角权重，半宽 1/12，环绕处理。色轮权重取自线性亮度：
阴影 `(1-l)²`、高光 `l²`、中间调 `1-阴影-高光`（≥0）。
曲线：每通道 5 个控制点（x 固定 0/.25/.5/.75/1），先烤成 4×256 表，
CPU 与 GPU 都采样同一张表（先逐通道、后主曲线）。LUT：`.cube` 解析 + 三线性采样；
GPU 侧用标准打包 2D 纹理（宽 N²、高 N）做 R/G 双线性 + B 线性近似。
LUT 文件本身不嵌进工程，只存路径；文件丢失时 `lutEnabled` 保留但采样跳过，
UI 应提示（不静默变恒等）。

## 2. 面板与停靠

- `ui/ColorPanelWidget`：一个 widget，两个家——检查器的“调色”页
  （`InspectorWidget` 的 Tab）与独立的“调色” Dock（`MainWindow`，默认与素材库
  tab 在左侧，架构 §6：调色放左）。两个实例编同一个 model，选区/播放头变化时
  一起刷新。
- 示波器（波形/矢量/直方图）是 CPU 分析：`ColorScopes::compute` 对调色后的小图
  （320×180）算三组数据，画在面板顶部；它不参与调色本身。
- 预览分流规则（`MainWindow::renderPreviewAtPlayhead`）：场景恰好是一个带调色
  的视频片段、且无美颜/抠像/遮罩/柔化/焦点时，合成器输出**未调色**画面，
  由 `PreviewWidget` 的 grade 管线在 GPU 上调色；其它场景一律走 CPU 调色。
  grade 管线建不起来时自动 CPU 回退，预览永远不错色。
  （一帧里两个片段各带不同调色时，整帧级 GPU 调色表达不了——此时走 CPU，
  这是分流规则，不是 bug。）

## 3. 美颜与抠像

- 美颜（W5 路线）：小半径盒式模糊近似高斯降噪 + 轻微提亮；有遮罩才分区，
  无遮罩整帧轻处理。遮罩尺寸不符时忽略遮罩（整帧处理），不报错、不中断渲染。
- 互斥规则（沿用 W5 已验证限制）：**美颜与人像抠像背景不能同时开**
  （`beautyKeyingConflict()`），两者都要人像遮罩。绿幕色度键不用人像遮罩，
  与美颜不冲突。注意：v2 暂未移植人像分割模型，所以人像抠像背景的开关本身
  是 S4 之后的事；互斥判断函数已在 core 里，面板先按规则写文案。
- 色度键：键色 + 容差 + 柔和（羽化带），逐像素 alpha。
- 形状遮罩：矩形/圆形/钢笔多边形（简化版）+ 羽化 + 反向；归一化坐标。

## 4. 柔化/突出（DogSC MosaicClip 语义）

只有 blur / spotlight 两种（像素块马赛克已在上游退役，不加回来）。
强度 0–1（默认 0.55）、突出压暗度默认 0.22（上限 0.75）、进出过渡默认各 0.3s、
圆角默认 0.08（按矩形短边归一化）。定义在**源画面坐标系**：在解码帧上先做、
再进缩放/3D 变换，所以天然跟随运镜。`progressAt()` 处理淡入淡出；
`progress == 0` 时跳过，不浪费算力。

## 5. 运镜（DogSC 语义，行为抄规格）

- 自动缩放：点击按空间邻近（0.15 归一化）+ 时间邻近（1.5s）分组 → 质心为稳定
  焦点（ clamp 到 0.08 安全边距内）→ 保持 0.9s → 欠阻尼弹簧进出。
  手动片段原样保留，重规划时不动。
- 弹簧：质量/刚度/阻尼三参数，屏幕与光标各一套；默认刚度 120、阻尼 14，
  欠阻尼（`damping² < 4·m·k`），解析步响应，中间过冲、末尾收敛到 1。
- 屏幕 3D：位置/大小/X·Y 倾斜/Z 旋转/透视；`projectScreenQuad()` 给出精确投影四边形。
  **CPU 渲染器只做余弦缩短近似**（QPainter 是仿射的，做不了真透视四边形）；
  精确透视是 GPU 预览路径的事，S3 文档里写清楚，不假装 CPU 也有。
- 焦点虚化：3D 与缩放同时有焦点效果时**只用 3D 的**，绝不叠两层全帧模糊
  （`resolveFocus()`）。形状径向/线性、目标锚点/鼠标/固定点保留在模型里。
- 光标独立轨道：轨迹与视频分开存（`PointerTrack.samples`），样式/大小/
  静止隐藏（延迟）/时间校准（毫秒偏移）可调；已烧进导入视频的光标无法隐藏
  或替换，必须重录（产品语义，写进帮助文案，不做假承诺）。

## 6. 画布构图（DogSC CanvasStyle 语义）

裁切（归一化矩形）、留白（短边分数）、圆角/描边/阴影、内容缩放与位置，
全部归一化坐标。样机外框是**几何算出来的**：窗口/浏览器/手机/平板变体，
外框矩形、工具栏矩形、内容矩形、内外圆角、配色、标题、地址栏、红绿灯圆点
都在 `frameGeometry()` 里算；未知样式解码时映射到最近的核心样式，
老工程不丢。注意：S3 的裁切作用在**合成后的整帧**上（单主素材场景等价于
裁源画面）；多层合成时逐层裁切是后续工作。

## 7. 求值链挂接

- `Clip` 新增：`grade` + `gradeEnabled`、`beauty`、`chromaKey`、`mask` + `maskEnabled`。
- `TimelineModel` 新增工程级状态：`canvasStyle`、`mosaics`、`clickEvents`、
  `manualZoomSegments`、`autoZoomEnabled`、`screenMotions`、`pointerTrack`、
  `zoomFocus`、`screen3DFocus`、`screenSpring`、`cursorSpring`。
  全部进 `toJson`/`fromJson`（S2 文件缺失时取默认值，老工程能打开）。
- `TimelineEvaluator::evaluate()` 把每片段的调色/美颜/抠像/遮罩抄到 `FrameLayer`，
  把画布/活动柔化（含进度）/自动缩放系数与焦点/3D 姿态/光标采样与可见性/
  胜出的焦点效果抄到 `FrameScene`；每层的场景运动也抄一份，供 `drawLayer` 用。
- `TimelineFrameRenderer::render()` 每层管线：抠像 → 遮罩 → 美颜 → 调色 →
  柔化（仅主故事线层）；合成后：焦点虚化 → 光标 → 画布。
  `applyGrade=false` 时跳过调色一级（GPU 预览路径）。

## 8. 已知缺口（S3 不假装已做）

1. GPU 调色与 CPU 调色的逐像素一致性未在 CI 验证（无 GPU），待真机对照。
2. CPU 渲染器的 3D 倾斜是余弦缩短近似，不是真透视（§5）。
3. 人像分割模型未移植：美颜暂无真人像遮罩（整帧轻处理），人像抠像背景开关未接。
4. 画布裁切作用在合成后整帧，不是逐层裁源画面（§6）。
5. 曲线编辑器是 5 点数值表，不是拖拽式曲线板；HSL 是数值 spinbox，不是色轮盘。
6. 美颜的盒式模糊是近似高斯；焦点虚化同理。8K 下逐像素 CPU 调色/美颜的
   速度未测——代理 + GPU 预览是 S1 的路线，CPU 路径只保证正确，不保证快。
7. 光标样式目前只画箭头（样式名已存模型，渲染只实现箭头 + 点击圆环）。
